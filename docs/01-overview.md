# Что делает сервис — простыми словами

Если по-простому, это касса и диспетчер для сервиса генерации картинок и видео нейросетями.

## Что может сделать пользователь

1. **Пополнить баланс.** Пользователь платит деньги и получает внутреннюю валюту — токены.
   Сервис начисляет их, даже если платёжная система по ошибке сообщила об одной оплате
   20 раз: начисление будет одно.
2. **Заказать генерацию.** Например: «нарисуй кота в космосе», модель `image-fast`,
   вот две картинки-примера. Сервис сразу:
   - проверяет, хватит ли токенов (картинка стоит 2, длинное видео 25);
   - списывает токены;
   - выдаёт номер заказа, а работа идёт в фоне.
3. **Узнать, как дела с заказом.** По номеру видно, готово ли, и если готово, то ссылку
   на результат. Ещё видна история: «сначала пробовали alpha, она отказала, потом beta,
   получилось».
4. **Посмотреть баланс** и выписку, на что ушли токены и откуда пришли. Как выписка
   по банковской карте.

## Какую пользу это даёт

Сам сервис картинки не рисует. Он передаёт заказ внешним нейросетям (провайдерам),
а они ненадёжные: падают, тормозят, отказывают («это нарушает правила»), иногда молчат
совсем. Сервис прячет этот хаос от пользователя:

- **Заказ не теряется.** Если провайдер отказал или завис, сервис сам отдаёт задачу
  запасному. Пользователю не нужно ничего нажимать повторно.
- **Деньги не пропадают.** Если не справился никто, токены возвращаются автоматически.
- **Нет двойных списаний и двойных возвратов.** Ровно одно списание, максимум один возврат,
  ровно одно начисление за оплату, даже при сбоях и повторах.
- **Отказ по делу не тратит время.** Если сам запрос сформирован неправильно, его отклонит
  любой провайдер. Сервис сразу говорит «нет» и возвращает токены, а не гоняет заказ
  по всем провайдерам.
- **Защита от перегруза.** Одновременно можно держать не больше 3 активных заказов.

## Аналогия

Это как служба доставки еды, которая работает с несколькими ресторанами. Клиент платит
при заказе. Если первый ресторан не может приготовить блюдо, служба сама передаёт заказ
во второй. Если не может никто, деньги возвращают, причём один раз, а не дважды
и не ноль раз.

Если первый ресторан всё-таки привёз еду с опозданием, когда заказ уже передали другому,
служба должна решить, что с этим делать, чтобы клиент не получил и еду, и возврат денег.
Это и есть «правило 6» из задания.

## Кто на самом деле пользователь

Интерфейса нет, всё работает через API. Пользователь в задании условный: на деле этим API
будет пользоваться приложение или сайт, а главное в задании — надёжная логика внутри.
